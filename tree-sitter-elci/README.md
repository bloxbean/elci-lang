# tree-sitter-elci

A [tree-sitter](https://tree-sitter.github.io/) grammar for Elci, for syntax highlighting, folding
and structural navigation in editors. It follows the formal grammar in
[`docs/GRAMMAR.md`](../docs/GRAMMAR.md), which describes what the Elci compiler's parser accepts.

It is not published to npm or crates.io yet.

## Contents

| Path | What it is |
| --- | --- |
| `grammar.js` | the grammar |
| `src/scanner.c` | the external scanner: layout and the `-` of `f -1` |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `tree-sitter generate`, committed as usual for tree-sitter grammars |
| `queries/highlights.scm`, `locals.scm`, `folds.scm`, `indents.scm` | editor queries |
| `test/corpus/*.txt` | parse-tree tests |
| `test/highlight/*.elm` | highlighting tests |
| `script/parse-all.sh` | parses every `.elm` file in the repository |

## Build and test

You need Node.js and a C compiler. From this directory:

```sh
npm ci                                  # installs the pinned tree-sitter CLI
npx tree-sitter generate --abi 14       # after changing grammar.js; ABI 14 suits most editors
npx tree-sitter test                    # corpus and highlighting tests
script/parse-all.sh                     # every .elm file in the repository, with no ERROR or MISSING node
npx tree-sitter parse ../examples/vesting/src/Vesting.elm
npx tree-sitter build -o elci.so        # a shared library for an editor
```

`script/parse-all.sh` skips `src/test/resources/syntax/unsupported` and `malformed`, which the
compiler rejects on purpose.

To see highlighting in a terminal, point the CLI at a configuration whose `parser-directories`
contains the directory that holds `tree-sitter-elci`, then run
`npx tree-sitter highlight --config-path config.json ../examples/functional/src/Main.elm`.

## How the grammar reads layout

Elci's parser reads layout from token columns (see "Layout" in `docs/GRAMMAR.md`). The external
scanner keeps a stack of the open `let` and `case` blocks and their columns, and emits zero-width
tokens:

- after `let` and `of`, a token that opens a block at the column of the next token;
- a separator when a line starts at the block's column;
- a close when a line starts left of the block's column, before `in`, `then`, `else`, `of`, `)`,
  `]`, `}` or `,`, and at the end of the file.

The top level is a block at column 1. The parser tells the scanner which tokens it can accept, so no
separator or close is emitted inside brackets unless a `let` or `case` is open there, as in Elci.
Lines that start with `->`, `=`, `:` or `|` never separate items, because Elci reads those tokens at
any column. The scanner looks past comments to find the column of the next token.

The scanner also decides the `-` of `f -1`: a minus after whitespace, touching its operand, where a
function argument can follow, is a negative argument. Elsewhere `-` is subtraction or negation.
Field access (`r.field`) uses a `.` that touches the token before it; an accessor (`.field`) uses a
`.` that does not.

## Differences from the compiler's parser

When this grammar was written, it read the same trees as the compiler's parser for every `.elm` file
in the repository and every complete module in the documentation. It differs in a few places that
no formatted code relies on.

It rejects some things the compiler's parser accepts:

- spaces around the `.` of a qualified name in a module name, an import, a type or a pattern
  (`Maybe . Just`);
- a type variable applied to arguments (`a Int`), and arguments after a parenthesized, record or
  tuple type, which the type checker rejects anyway;
- `_` as a type parameter, record field or `as` name, and names that start with `_`;
- `(..)` after a lowercase name in an exposing list;
- a `let` with no declarations;
- digits other than ASCII `0`-`9`.

It accepts some things the compiler rejects:

- chained comparisons and mixed associativity (`a < b < c`, `f <| x |> g`), which it groups to the
  left;
- tuples with more than three elements;
- tabs;
- a signature followed by the definition of a different name;
- a closing bracket in the column of a `case`'s branches.

It reads one thing differently: in `r{- comment -}.field`, the compiler sees an accessor argument,
`r .field`, and tree-sitter sees a field access, because a comment does not separate tokens for
tree-sitter.

## Editor setup

Elci files use the `.elm` extension, like Elm. Each editor below needs a rule that picks Elci for
the files of an Elci project, for example the `.elm` files under a directory that contains
`elci.toml`.

The highlight queries use tree-sitter's standard capture names, and later patterns override earlier
ones, as in tree-sitter-highlight and Neovim.

### Neovim

Build the parser and install it with the queries:

```sh
npx tree-sitter build -o ~/.config/nvim/parser/elci.so
mkdir -p ~/.config/nvim/queries/elci
cp queries/*.scm ~/.config/nvim/queries/elci/
```

Then choose the file type and start tree-sitter for it (Neovim 0.10 or later):

```lua
vim.filetype.add({
  extension = {
    elm = function(path)
      return vim.fs.root(path, "elci.toml") and "elci" or "elm"
    end,
  },
})
vim.api.nvim_create_autocmd("FileType", {
  pattern = "elci",
  callback = function()
    vim.treesitter.start()
    vim.wo.foldmethod = "expr"
    vim.wo.foldexpr = "v:lua.vim.treesitter.foldexpr()"
  end,
})
```

`indents.scm` uses nvim-treesitter's capture names; it takes effect with nvim-treesitter's
`indentexpr`.

### Helix

Add the grammar and the language to `~/.config/helix/languages.toml`:

```toml
[[grammar]]
name = "elci"
source = { git = "https://github.com/bloxbean/elci-lang", rev = "<commit>", subpath = "tree-sitter-elci" }

[[language]]
name = "elci"
scope = "source.elci"
grammar = "elci"
file-types = [{ glob = "<your project>/**/*.elm" }]
roots = ["elci.toml"]
comment-tokens = ["--"]
block-comment-tokens = { start = "{-", end = "-}" }
indent = { tab-width = 4, unit = "    " }
```

Run `hx --grammar fetch` and `hx --grammar build`, and copy `queries/*.scm` to
`~/.config/helix/runtime/queries/elci/`. Helix's themes use some other capture names, such as
`namespace` for `module` and `variable.other.member` for `property`; rename those in your copy.

### Zed

A Zed extension names the grammar in its `extension.toml`:

```toml
[grammars.elci]
repository = "https://github.com/bloxbean/elci-lang"
rev = "<commit>"
path = "tree-sitter-elci"
```

and describes the language in `languages/elci/config.toml`, next to a copy of
`queries/highlights.scm`:

```toml
name = "Elci"
grammar = "elci"
path_suffixes = ["elm"]
line_comments = ["-- "]
```
