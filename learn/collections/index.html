Lists, dictionaries, maps and arrays

Elci has four collection types. List is the everyday sequence, Dict stores values under comparable keys as Elm’s Dict does, Map is the ledger’s own key/value map, and Array gives constant-time indexed reads. This page covers all four, and what they cost on-chain.

Lists

Section titled “Lists”

A list holds any number of values of one type: [ 1, 2, 3 ] is a List Int. :: puts an element in front of a list, ++ joins two lists, and you take lists apart with patterns:

amounts is [ 0, 10, 20, 30 ], so the result is 60 + 4. [] matches the empty list, and first :: rest matches a list with a first element and the rest after it. Most list functions are this shape: handle the empty list, then handle one element and recurse on the rest. List.sum already does this one; writing it yourself shows the pattern.

Sorting

Section titled “Sorting”

List.sort sorts values of a comparable type: numbers, strings, bytes and ledger hashes, and lists and tuples of them. Records and custom types are not comparable, so sort them by a key with List.sortBy, or with a comparison function that returns LT, EQ or GT:

The sorts are stable: carol and bob bid the same amount and keep their order. Sorting costs budget, so sort on-chain only when the result depends on the order.

Dictionaries

Section titled “Dictionaries”

Dict k v stores values of type v under keys of type k, with Elm’s Dict API. Import it as in Elm, with import Dict exposing (Dict). Keys must be comparable: Int, String, Bytes, ledger hashes such as PubKeyHash, and lists and tuples of these.

Alice has 125, and Dave has no balance, so balanceOf gives 0. The bindings come out in key order, not in the order they went in.

The module has all of Elm’s Dict functions, with the same names, argument orders and results:

GroupFunctions
Buildempty, singleton, insert, update, remove
QueryisEmpty, member, get, size
Listskeys, values, toList, fromList
Transformmap, foldl, foldr, filter, partition
Combineunion, intersect, diff, merge

Core modules has every signature. A Dict is stored as a Plutus map whose keys are kept in ascending order. What that means for you:

  • Key order, always. keys, values, toList and the folds follow ascending key order, as in Elm. fromList keeps the last value of a repeated key, and union prefers the left dictionary’s value.

  • == works. Two dictionaries with the same bindings are equal, however they were built:

  • Lookups are O(n). A Dict is a list of pairs, not a tree. get, member, insert and remove walk from the smallest key and stop at the first key that isn’t smaller, at about 1.1 million CPU units per key passed. fromList sorts, in O(n log n).

  • Datums can hold dictionaries. A Dict encodes as a Plutus map with sorted keys. A datum, redeemer or parameter whose keys are out of order or repeated fails to decode, so an attacker can’t hide a key where lookups stop early. See datums and redeemers.

Maps

Section titled “Maps”

Map k v is the ledger’s own key/value map: an unsorted list of pairs, with keys compared by their Data encoding. The transaction’s maps are Maps, such as txInfo.withdrawals (Map Credential Int) and txInfo.redeemers (Map ScriptPurpose Data). Their keys are not comparable, so they can’t be Dicts. Use a Map for those, and for keys of your own that are not comparable, such as a custom type. Write import Map to use its functions; the type name Map is always in scope.

Asset is a custom type, so it can’t be a Dict key, but it can be a Map key. The new key Token "SILVER" comes first. Asset only illustrates a key: the ledger’s own amounts of ada and tokens, such as an output’s value, are Values, with their own Value module.

Because a Map is the ledger’s representation:

  • Lookups are O(n). get, member, insert and remove scan the pairs from the front, at about 1.1 million CPU units per key passed. Building a map with fromList is O(n²). That’s fine for small maps; for your own data with comparable keys, a Dict builds faster.

  • Maps are not sorted. keys, values and toList follow the map’s own order. insert and fromList put a new key at the front, and map and filter keep the existing order. When you need key order, sort the bindings with List.sortBy Tuple.first, or use a Dict.

  • Maps can’t be compared with ==:

Keys and values can be any type that has a Data encoding, including your own records and custom types and ledger types such as PubKeyHash.

Arrays

Section titled “Arrays”

Array a is an immutable sequence with constant-time get and length, like Elm’s Array. It is a Plutus V3 array (CIP-138). As with Dict and Map, import the module for its functions:

Array.get returns Nothing for an index outside the array. The module also has empty, isEmpty, initialize, repeat, toList, toIndexedList, map, indexedMap, foldl, foldr, filter and slice. In slice start end, a negative index counts from the end, so Array.slice 0 -1 tiers drops the last element.

Arrays have two important limits:

  • No updates. There is no set or push. Build a List, then convert it once with Array.fromList, which is O(n).

  • No Data encoding. An array can’t be a datum, redeemer or parameter, and can’t be stored inside a record, custom type, tuple, list or map:

    Keep a List in your data, and convert it where you need many indexed reads.

Choosing a collection

Section titled “Choosing a collection”

Everything a script does costs budget, and traversals are where budgets go. Here are nine lookups into the same 100-element list, done two ways. This version uses an array:

The other version is the same program with values = List.range 1 100 and nth index values in place of Array.get index values, using the nth function from earlier on this page:

VersionCPUMemory
List with nth500,299,6652,264,391

Both results are 459, and both build the same list. The array version also converts it once, but it wins on the lookups: each nth walks up to 90 elements, while each Array.get takes a constant number of steps.

  • Use a List for data, and when you process every element once (map, filter, foldl, any).
  • Use a Dict for data you build or look up by a comparable key, including datums.
  • Use a Map for the ledger’s maps, such as txInfo.withdrawals, and for keys that are not comparable.
  • Use an Array when you read many elements by index. Convert once, then read many times.
