Coming from Elm

If you know Elm 0.19, you already know most of Elci’s syntax. This page lists what carries over and every difference that matters, so you can skip the parts of the Learn section you don’t need.

What stays the same

Section titled “What stays the same”
  • The syntax of Elm 0.19.1: modules and exposing, import … as … exposing, type and type alias, case, let, if, lambdas, records, tuples of two or three elements, |>, <|, >> and <<. The grammar defines it exactly and lists the Elm syntax Elci rejects.
  • Immutable values and pure functions. Evaluation is strict, as in Elm: arguments and let values are evaluated before use, and only the chosen branch of if and case runs.
  • Hindley–Milner type inference, generic functions (a -> a), and generic type aliases and custom types.
  • Exhaustive case checking. Redundant patterns are errors.
  • Local type annotations in let.
  • Records: field access, updates, destructuring and accessor functions such as .price, as in List.map .price items. A field of a value from another module reads as in Elm: Config.settings.fee.
  • The core library’s default imports: Basics with exposing (..), List, Maybe with Maybe(..), Result with Result(..), String, Tuple and Debug. Their functions have Elm’s names, argument orders and edge cases: max, compare, identity, Maybe.withDefault, List.head, List.range, List.sortBy, Result.andThen, Tuple.first, String.fromInt and more.
  • Elm’s name rules: your own declarations shadow imports, and two imports exposing one name make it ambiguous where you use it.
  • No typeclasses, with Elm’s constrained type variables comparable, appendable and compappend.
  • Operators as functions, such as List.foldl (+) 0, and ^ for powers.
  • Types that nothing determines, as in [] == [] or Result.withDefault 0 (Ok 5), need no annotation.
  • // truncates toward zero, and modBy and remainderBy follow Elm’s sign rules: modBy takes the sign of the divisor, remainderBy the sign of the dividend.
  • Negative arguments: modBy 3 -7 passes -7, while a - 1 and a-1 subtract.
  • elm-format 0.8.8 style, apart from one pitfall described below.

The program model

Section titled “The program model”

Elm programs run in a browser. Elci programs are scripts that the Cardano ledger runs when it validates a transaction.

ElmElci
main : Program flags model msgA handler function that returns Bool, named in a [validators.<name>] table of elci.toml
Html, Browser, Cmd, Sub, Task, portsNone. A script has no effects: it reads its inputs and approves or rejects
elm.json and the package registryelci.toml. No Elm packages; share code as source directories
elm make, elm repl, elm reactorelci check, elci build, elci test, and elci eval for a function project
Runtime exceptions are rareFailing is normal: any failure rejects the transaction

That last row changes how you think about errors. On-chain, failing is often the right answer: a malformed datum, a missing signature or a division by zero all reject the transaction, and nothing else happens. In Elm, n // 0 evaluates to 0. In Elci, it fails the script, as do modBy 0 and remainderBy 0.

The core library

Section titled “The core library”

Elci’s core library is Elm’s, imported by default in every module:

ModuleWhat Elci has
Basicsnegate, abs, min, max, clamp, compare and Order, identity, always, not, xor, modBy, remainderBy, ^
Listall of Elm’s List except map4 and map5
MaybewithDefault, map, map2, map3, andThen
ResultOk, Err, map, map2, map3, andThen, withDefault, toMaybe, fromMaybe, mapError
Tupleall of Elm’s Tuple
StringfromInt, isEmpty, append, concat, join
Debugtrace

Core modules has every signature. What is still missing:

ElmIn Elci
toFloat, round, sqrt, pi and the other Float functionsNot available: there is no Float
map4 and map5 in List, Maybe and ResultNot available. Nest map3, or use case
String.length, toInt, split, slice, fromFloat…Not available. Bytes.length (Bytes.fromString s) is the byte length
CharNot available
SetNot available. Use a Dict k Bool or a List
Debug.log, Debug.todo, Debug.toStringDebug.trace : String -> a -> a, and String.fromInt for numbers

A name Elci lacks is an error that says what to use or lists what the module has:

One import rule differs from Elm: a name you list explicitly, as in import Utils exposing (clamp), takes precedence over the default import of Basics.clamp instead of being ambiguous. Modules outside the default imports, Bytes, Dict, Map, Array, Value and Julc.Data, need their own imports, as Dict and Array do in Elm.

Dict, Map and Array

Section titled “Dict, Map and Array”

Dict has all of Elm’s Dict API, but it is stored differently:

Elm DictElci Dict
Importimport Dict exposing (Dict)The same; the type Dict k v is always in scope
Keyscomparablecomparable, which includes Bytes and ledger hashes such as PubKeyHash
StructureBalanced treeA Plutus map with its keys in ascending order
get, insert, removeO(log n)O(n): they stop at the first key that isn’t smaller
fromListO(n log n)O(n log n), and O(n) for sorted input
Order of keys, toList and the foldsAscending keysThe same
==Compares bindingsThe same

In a datum, redeemer or parameter, a Dict is a Plutus map with sorted keys, and a map whose keys are out of order or repeated fails to decode.

Elci also has Map, which Elm doesn’t. A Map k v is the ledger’s own map: an unsorted association list whose keys may be any type with a Data encoding, such as Credential. The transaction’s maps, such as txInfo.withdrawals and txInfo.redeemers, are Maps. A map keeps its own order (insert puts a key first), has no ==, and Map.fromList is O(n²). Use Dict for keyed data of your own, and Map where the ledger or a key that isn’t comparable requires it.

Array resembles Elm’s Array: get returns a Maybe and slice accepts negative indexes. It has no set, push or append, and an array can’t be stored in data (datums, redeemers, records, lists and so on). Build a List and convert it once with Array.fromList.

Elci also has a Value module, for the ledger’s amounts of ada and native tokens, such as an output’s value and the transaction’s mint. It has no Elm counterpart; see Value.

Your data is Plutus Data

Section titled “Your data is Plutus Data”

In Elm, you convert values to JSON with hand-written encoders and decoders. In Elci, every datum, redeemer and parameter is Plutus Data, and the encoding is derived from your types:

TypeEncoding
RecordConstructor 0, fields sorted by field name
Custom typeConstructor numbered by declaration order (first is 0), with its values as fields
TupleConstructor 0, fields in position order
BoolFalse is constructor 0, True is constructor 1
Maybe aNothing is constructor 0, Just is constructor 1
Result e aOk is constructor 0, Err is constructor 1: the reverse of PlutusTx’s Either
List aA Data list
Dict k vA Data map with its keys in ascending order
Map k vA Data map, in the map’s order
Int, Bytes, StringAn integer, a byte string, and UTF-8 bytes

Maybe’s tags are the reverse of those used by Julc’s Java Optional and the ledger’s own optional values, where the present value is constructor 0. They aren’t interchangeable: Julc.Data.fromOptional and toOptional convert between them. You can see Elci’s tags by encoding a list of Maybe values:

Error messages

Section titled “Error messages”

Elci’s error messages follow Elm’s: they quote the line of source, say what is wrong in terms of your program and suggest a fix.

As in Elm:

  • A type mismatch names the argument, branch, list element, operator side, annotation or field whose type differs, and writes types as in source.
  • A case that doesn’t cover every value lists the missing patterns, such as Nothing and Just (Err _).
  • A misspelt name gets a suggestion, such as did you mean `List.length`?.
  • A run reports every error it finds, one per top-level declaration, in source order. Type errors are reported once there are no syntax, import or qualified-name errors.

What differs:

  • The first line is path:line:column: ELCIxxxx: message, not a -- TYPE MISMATCH -- banner. Editors and scripts parse this line, and each code keeps its meaning between releases.
  • --report=json prints each error as one JSON object on its own line, and its fields are Elci’s own: code, path, line, column, message, hints, excerpt and context. See diagnostics.
  • elci explain ELCI2002 prints a longer explanation of a code, with an example and its fix.

An elm-format pitfall

Section titled “An elm-format pitfall”

elm-format 0.8.8 is Elci’s formatter, but it stores integer literals as 64-bit numbers. It silently changes a literal larger than about 9.2 × 10¹⁸ into a different number. Elci’s Int has no limit, so compute such values instead, for example 1000000000 * 1000000000 * 1000000000.

Tooling

Section titled “Tooling”
  • The repository has a tree-sitter grammar for highlighting, folding and indentation in Neovim, Helix and Zed.
  • There is no Elci language server. The Elm language server doesn’t know Elci’s modules, so trust elci check over its diagnostics. An editor integration can run elci check --report=json and read each error’s location, message and hints.
  • elci eval runs a function project and shows the result and its cost, which is the closest thing to elm repl. Values, functions and types shows how to set one up.
  • elci test replaces elm-test, and adds transaction scenarios and property tests. See Unit tests.
