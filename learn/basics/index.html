Values, functions and types

This page covers the building blocks of Elci: basic values and their types, operators, functions and their signatures, lambdas, partial application and generic functions. Every example is a complete module that you can run.

Set up a playground

Section titled “Set up a playground”

A function project runs one value with elci eval, which makes it the quickest way to try things out:

The project’s elci.toml ends with an [entrypoint] table, which points elci eval at the value main in module Main:

and src/Main.elm is:

To try an example from these pages, replace src/Main.elm with it and run elci eval . again. Keep the module Main exposing (main) line and a main value, because that’s what elci.toml names.

elci eval compiles main to a Plutus script, runs it on Julc’s virtual machine and prints:

  • the value, written in Elci syntax;
  • the execution budget the script used, in CPU and memory units. The ledger charges fees for these units;
  • a trace: line for each Debug.trace message, if there are any.

Add --builtins to also list every Plutus builtin function that the script called.

Basic types

Section titled “Basic types”
TypeExamplesNotes
Int42, -7, 1000000Whole numbers of any size. There is no Float.
BoolTrue, False
String"GOLD", "line\n"Text. Join with ++, compare with == or <. The String module has String.fromInt and more.
BytesBytes.fromString "GOLD"Raw byte strings, from import Bytes
()()Unit: a type with exactly one value, used for “nothing to say”

Strings support the escapes \n, \r, \t, \" and \\. There is no Char type.

Values and functions are both defined with =, each with a type signature above it. A function lists its parameters before the =:

The builtin lines show the two operations the script performed. A lovelace is the smallest unit of ada, and on-chain amounts are always whole lovelace, which is one reason Elci doesn’t need Float.

Numbers

Section titled “Numbers”

Int has arbitrary precision: +, - and * are exact and never overflow.

There are three ways to divide:

OperationResult
a // bInteger division, truncating toward zero: 7 // 2 is 3 and -7 // 2 is -3
modBy d nRemainder with the sign of the divisor d: modBy 3 -7 is 2
remainderBy d nRemainder with the sign of the dividend n: remainderBy 3 -7 is -1

^ raises an integer to a power, and the prelude, which every module imports, provides the other everyday functions: negate, abs, min, max and clamp.

clamp low high x keeps x between the bounds. Core modules lists the whole prelude.

Dividing by zero (with //, modBy or remainderBy) doesn’t return a value: it fails the script, and a failing validator rejects the transaction. / and fractional literals such as 1.5 are rejected by the compiler:

To work with fractions, scale your integers. For example, store a percentage in basis points (1% is 100).

Booleans and comparisons

Section titled “Booleans and comparisons”
OperatorMeaning
==, /=Equal, not equal. Works on numbers, strings, bytes, lists, tuples, records, custom types and dictionaries, but not on functions or Maps
<, <=, >, >=Ordering, for comparable types: numbers, strings, bytes, and lists and tuples of them
&&, ||And, or. The right side is evaluated only when needed
notNegation: not True is False

Strings order by their UTF-8 bytes, so "Zebra" < "apple": capital letters come first. compare a b returns LT, EQ or GT. Booleans, records and custom types have no order, and True < False is a compile error.

Comparisons can’t be chained. Write low < x && x < high instead of low < x < high:

Functions and signatures

Section titled “Functions and signatures”

A call lists its arguments after the function name, separated by spaces: toLovelace 25, isValidFee 200000. Parentheses group expressions, not arguments: not (isValidFee 5).

Every top-level declaration needs a type signature. In a signature, -> separates the parameter types from the result type. Int -> Int -> Int takes two integers and returns one. Leaving a signature out is an error:

Inside a function, types are inferred, so local values need no annotations (you may still add them). When types don’t fit together, the compiler shows you where and suggests a fix:

The first line gives the file, line and column, and a code you can look up in the diagnostics reference. Below it are the line itself, with a caret under the problem, and sometimes a Hint: line with the likely fix.

Lambdas, currying and partial application

Section titled “Lambdas, currying and partial application”

\x -> expression is an anonymous function, or lambda. \n total -> n + total takes two arguments.

Every function takes its arguments one at a time. add : Int -> Int -> Int is a function that takes an Int and returns a function Int -> Int, so you can supply only the first argument:

addFive is add with its first argument already supplied. List.map addFive adds 5 to each element (giving [ 6, 7, 8 ]), and List.foldl add 0 sums them.

Operators are functions too. Written in parentheses, (+) is the function \a b -> a + b, so List.foldl (+) 0 also sums a list, and (*) 2 doubles a number.

Elci is strict: a partial application evaluates the arguments you give it straight away. add (10 // 0) fails at that point, not later when the second argument arrives.

Generic functions

Section titled “Generic functions”

A lowercase name in a signature, such as a, is a type variable: the function works for any type in that position.

twice is used with strings and with integers. The compiler specializes a generic function for each concrete type it’s used with.

Bytes and unit

Section titled “Bytes and unit”

Byte strings are everywhere on Cardano: key hashes, token names and script hashes. The Bytes module wraps the Plutus byte-string builtins:

“GOLD” is the 4 bytes #474f4c44, and its SHA-256 hash is 32 bytes. Byte strings are written in hex after a #. Bytes, hashes and bits covers the whole module.

The unit value () carries no information. You met it in Your first validator as a datum and redeemer that the validator ignores.
