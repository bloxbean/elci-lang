Custom types and pattern matching

A custom type lists the shapes a value can take. Custom types and exhaustive pattern matching are the most useful part of Elci for contracts. A redeemer is usually a custom type with one constructor per action, and the compiler checks that your validator handles every one.

How constructors are encoded

Section titled “How constructors are encoded”

Constructors are numbered in declaration order, starting at 0: Deposit is 0, Withdraw is 1 and Close is 2. On-chain, a value is a Plutus Data constructor with that tag and its values as fields. Julc.Data.encode shows the encoding:

Caution

Reordering, inserting or removing constructors changes their tags, and with them the encoding of every datum and redeemer of that type. Add new constructors at the end, and pin the encoding with expected-abi (see Build and deploy).

Bool is encoded the same way: False is constructor 0 and True is constructor 1.

Maybe

Section titled “Maybe”

Maybe a is built in. It is either Just value or Nothing, and it’s how Elci represents “there may be no answer”. The Maybe module, which every module imports, has Elm’s helpers: withDefault, map, map2, map3 and andThen.

Nothing is constructor 0 and Just is constructor 1. Julc’s Java Optional uses different tags, so the two aren’t interchangeable. Julc.Data.fromOptional and toOptional convert between them when a Java library returns an optional value.

Result

Section titled “Result”

Result error value is either Ok value or Err error, as in Elm. Use it for a computation that can fail with a reason. The Result module, imported into every module, has map, andThen, withDefault, toMaybe, mapError and more:

On-chain, a validator returns Bool, so a Result usually ends in a case that returns False for an Err. As Data, Ok is constructor 0 and Err is constructor 1, the reverse of PlutusTx’s Either.

Nested patterns

Section titled “Nested patterns”

Patterns can nest constructors, tuples, records and lists. A list pattern such as [ x ] matches a list of exactly that length, and first :: rest matches any non-empty list:

Circle 5 doesn’t match [ Circle 0 ] (the list has three elements), so the (Circle _) :: rest branch adds 10. The same happens for Rectangle 2 3, which adds 20. The last element, Rectangle 4 4, is alone in its list and square, which adds 2.
