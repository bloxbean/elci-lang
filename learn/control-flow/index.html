Conditionals, let and pipelines

This page shows how to make decisions with if and case, name intermediate results with let, and chain function calls with pipelines. It ends with how Elci evaluates your code, which matters for both correctness and cost on-chain.

Pipelines and composition

Section titled “Pipelines and composition”

Nested calls read inside out. The pipe operator |> passes a value into the next function, so the steps read top to bottom:

x |> f means f x, and f <| x also means f x, which saves a pair of parentheses. >> and << compose two functions into a new one: (f >> g) x is g (f x), and (g << f) x is the same.

<| and |> have the lowest precedence of all operators, which is why not <| doubledIsLarge 5 needs parentheses when it’s part of a larger expression.

Strict evaluation

Section titled “Strict evaluation”

Elci evaluates eagerly, like Elm. Knowing exactly what gets evaluated matters on-chain, for two reasons: every step costs budget, and a single failure rejects the whole transaction.

if, case, && and || evaluate only what they need. Only the chosen branch of an if or case runs, and && and || skip their right side when the left side decides the answer. So put expensive or failing work inside a branch:

The other rules follow the same idea:

  • A function call evaluates the function, then its arguments from left to right, before the body runs. So Maybe.withDefault fallback m evaluates fallback even when m is a Just, and (&&) a b, the operator used as a function, evaluates b even when a is False.
  • A partial application such as add (10 // 0) evaluates its argument immediately.
  • In a validator, top-level values the handlers use are evaluated once per script run, before the handler is chosen. A failing top-level value therefore fails every purpose of the script.

Tip

In a validator, cheap checks that often fail belong on the left of &&. When the left side is False, the expensive right side never runs, which saves budget.

Debug.trace also costs budget on-chain, so remove traces before you deploy. Debugging and budgets has more.
