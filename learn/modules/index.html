Modules and imports

As a project grows, you split it into modules. This page shows how modules map to files, how exposing keeps helpers private, the forms of import, and which modules come with Elci. You also see how to use Julc’s Java libraries and how to share Elci code between projects.

One module per file

Section titled “One module per file”

Every file starts with a module header. The module name must match the file’s path under a source directory: Shop.Pricing lives in src/Shop/Pricing.elm.

Put both files in a function project (create the src/Shop directory) and run it:

A member pays 450 for the hat, and the scarf costs 300.

What a module exposes

Section titled “What a module exposes”

The exposing list in the header is the module’s public interface:

In the headerWhat other modules can use
priceOfThe function or value priceOf
ItemThe type alias Item, and for a record alias its constructor Item
TierThe custom type Tier, but not its constructors
Tier(..)The custom type Tier and all of its constructors

Everything else is private. memberDiscount above isn’t exposed, so Main can’t call it:

Keeping helpers private lets you change them without breaking other modules. In a validator module, expose the handlers and the datum and redeemer types that tests and off-chain code need.

Importing

Section titled “Importing”
ImportThen you can write
import Shop.PricingShop.Pricing.priceOf
import Shop.Pricing as PricingPricing.priceOf
import Shop.Pricing exposing (priceOf, Tier(..))priceOf, Member and Standard unqualified, and Shop.Pricing.Item
import Shop.Pricing exposing (..)Everything the module exposes, unqualified

A qualified name only works through an import in the current module. After import Shop.Pricing exposing (Tier(..)) without as Pricing, the name Pricing.priceOf means nothing:

Write Shop.Pricing.priceOf, or import the module as Pricing. Without any import of the module, Shop.Pricing.priceOf gives Module Shop.Pricing is not imported; add `import Shop.Pricing` . A misspelt qualified name gets a suggestion, such as did you mean `List.length`? for Lsit.length.

Your own declarations take precedence over imported names. If two imports expose different things under one name, using that name is an error that lists the qualified alternatives; write the one you mean, such as Pricing.priceOf.

Imports can’t form a cycle. If Shop.Pricing imported Main while Main imports Shop.Pricing, the build stops with:

Move the shared code into a third module that both import.

Modules that come with Elci

Section titled “Modules that come with Elci”

As in Elm, every module imports the core modules for you:

ModuleImported asContents
Basicsimport Basics exposing (..)The prelude: min, max, abs, negate, clamp, compare, identity, always, not, xor, modBy, remainderBy
Listimport Listmap, filter, foldl, head, range, sum, sort and the rest of Elm’s list functions
Maybeimport Maybe exposing (Maybe(..))withDefault, map, map2, map3, andThen
Resultimport Result exposing (Result(..))Ok and Err, with map, andThen, withDefault, toMaybe and more
Tupleimport Tuplepair, first, second, mapFirst, mapSecond, mapBoth
Stringimport StringfromInt, isEmpty, append, concat, join
Debugimport DebugDebug.trace, which records a message

The others you import yourself:

ModuleImportContents
Dictimport Dict exposing (Dict)Elm’s dictionaries, with comparable keys kept in order
Mapimport MapThe ledger’s key/value maps, for ledger data and keys that aren’t comparable
Arrayimport ArrayConstant-time indexed arrays
Valueimport Value exposing (Value)The ledger’s multi-asset values: lovelace and native tokens
Intervalimport IntervalTime ranges such as the transaction’s validity range: deadline checks
Tximport TxQuestions about the transaction: signers, spent outputs, payments, minted tokens, datums
Bytesimport BytesByte-string builtins: building, slicing, integers, bits and hashes
Julc.Dataimport Julc.Data as Dataencode and decode to and from Plutus Data, and Maybe adapters
Julc.Ledgerimport Julc.Ledger exposing (...)Ledger types: ScriptContext, PubKeyHash, TxOutRef and more

Core modules lists every function. Writing a default import yourself, such as import List exposing (head), is allowed and adds the names you expose. Test modules can also import the test library, Expect, Scenario and Property (see Unit tests). Source modules can’t, which keeps test code out of your scripts.

import Julc.Ledger exposing (..) exposes the ledger’s types but not their constructors. Name the constructors you need, as in exposing (Credential(..)). Reading the transaction covers the ledger types.

Julc’s Java libraries

Section titled “Julc’s Java libraries”

Julc ships on-chain libraries written in Java, such as MathLib, CryptoLib, AddressLib and ByteStringLib. They fill the gaps in the core modules, such as floor division and signature verification. To use one, give it a module name in elci.toml:

Then import it like any other module:

floorDiv rounds towards negative infinity, where // truncates towards zero.

The compiler reads the library’s Java source and compiles the functions you call into your script. Two rules differ from Elci modules:

  • The module name is whatever you choose in elci.toml. Julc.Math is a convention, not a built-in name. A core module’s name, such as Interval or Tx, can’t be used.

  • Expose names explicitly. import Julc.Math exposing (..) is rejected:

Standard library lists what each library provides, and Java libraries covers your own Java code.

Sharing code between projects

Section titled “Sharing code between projects”

There is no package manager. To reuse Elci code, keep it in its own source directory, for example a lib directory in a Git repository that several projects check out, and list that directory in each project’s source-directories:

A module in lib/Finance/Pricing.elm is then Finance.Pricing, imported like any other:

The library is compiled together with each project that uses it. A module name may appear in only one source directory. The core module names (Basics, List, Maybe, Result, String, Tuple, Map, Dict, Array, Value) are taken, and Set, Elci and names starting with Elci. are reserved for the core library. The elci-library example is a complete project.

Note

The compiler only compiles modules that your entrypoint or handlers import, directly or indirectly. A module that nothing imports isn’t checked, so import a new module before you rely on elci check to report its errors.
