elci.toml

Every Elci project has an elci.toml file at its root. This page lists every table and key, the values each one accepts and the rules the compiler enforces. Unknown tables and keys are errors, so a typo never goes unnoticed.

Format

Section titled “Format”

elci.toml uses a small, strict subset of TOML:

  • A table header is a line like [project] or [validators.treasury]. Each table may appear once.
  • Each setting is key = value on one line. A key may be quoted, as in "Julc.Math" = "...".
  • A value is either a quoted string, such as "src", or an array of quoted strings on the same line, such as ["src", "lib"].
  • Strings cannot contain escapes (\) or embedded quotes.
  • Comments are whole lines starting with #. A comment after a value is an error.
  • A key may appear only once per table.

Project kinds

Section titled “Project kinds”

A project configures either one or more [validators.<name>] tables or one [entrypoint] function, never both:

  • Validator projects produce deployable scripts. Use elci check, build, test and apply.
  • Function projects have an [entrypoint] for elci eval, which runs a function and prints its value and cost. They are for experiments and helper code, not for deployment.

[project]

Section titled “[project]”

Required in every project.

KeyRequiredValue
source-directoriesyesArray of directories holding source modules, relative to the project. At least one; each must exist.
targetyesMust be "plutus-v3-pv11-uplc-1.1.0", the only supported target.
julc-versionyesMust equal the Julc version the compiler is pinned to, currently "0.1.0-pre20-ebaf028-SNAPSHOT". elci --version prints it.
library-jarsnoArray of JAR paths, relative to the project, that contain on-chain Java library sources. See Java libraries.
expected-abinoPath of a committed abi.json to compare with the build. Function projects only; validators set it in their own table.

A module A.B must live at A/B.elm inside exactly one source directory. Two files defining the same module are an error.

[validators.<name>]

Section titled “[validators.<name>]”

One table per deployed script. The name becomes the output directory build/validators/<name>/ and the name you use in elci apply --validator, in tests and in --validator options. It must be 1 to 64 characters: lowercase letters, digits, - or _, starting with a letter.

KeyRequiredValue
boundaryyesMust be "julc-strict-v1", the strict data boundary.
spendat least one handlerHandler for spending, as "Module.function".
mintHandler for minting.
withdrawHandler for reward withdrawals.
certifyHandler for certificates.
voteHandler for governance votes.
proposeHandler for governance proposals.
parametersnoArray of deployment parameter names, in application order.
spend-datumno"required" (default), "optional" or "absent". Needs a spend handler.
expected-abinoPath of a committed abi.json; check, build and apply fail if the new ABI differs.

Rules:

  • Handlers name an exposed function as "Module.function", for example "Treasury.spend". Each handler key adds a purpose to the same script, so one table is always one script hash.
  • Parameter names start with a lowercase letter, followed by letters, digits or _, and must be unique. Every handler receives all parameters as its leading arguments, in this order, so their types must agree across handlers.
  • Handler signatures depend on the purpose and spend-datum:
HandlerRequired type
spendparameters -> datum -> redeemer -> ScriptContext -> Bool
spend with spend-datum = "optional"parameters -> Maybe datum -> redeemer -> ScriptContext -> Bool
spend with spend-datum = "absent"parameters -> redeemer -> ScriptContext -> Bool
mint, withdraw, certify, vote, proposeparameters -> redeemer -> ScriptContext -> Bool

Adding, removing or changing a handler changes the script and its hash. See validators and purposes and datums and redeemers.

[entrypoint]

Section titled “[entrypoint]”

The single function of a function project.

KeyRequiredValue
moduleyesThe module name, such as "Main".
functionyesAn exposed top-level function or value with a concrete type, such as "main".
purposenoOnly "function", the default.
boundarynoOnly "julc-strict-v1".

Validator purposes in [entrypoint] were removed. purpose = "spend" fails with a message telling you to move the handler into a [validators.<name>] table.

[java-modules]

Section titled “[java-modules]”

Maps Elm-style module names to on-chain Java library classes:

The key is the module name you import; the value is the fully qualified class name. A mapping is only read when a module imports it. A module name cannot be both a source module and a Java module. Julc.TypedMap and Julc.TypedArray are reserved by the core Map and Array modules and cannot be remapped. The core module names Basics, List, Maybe, Result, String, Tuple, Map, Dict, Array, Value, Interval and Tx, the reserved names Set and Elci, and names starting with Elci. cannot be keys. See standard library for the bundled classes.

[tests]

Section titled “[tests]”
KeyRequiredValue
source-directoriesnoArray of directories holding test modules. Default ["tests"].

A missing default tests directory simply means there are no tests. Test modules are never part of check, build or the deployed scripts. See unit tests.
