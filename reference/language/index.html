Language reference

This page is the compact reference for the Elci language: what is supported, how the syntax looks, how names resolve, how operators bind, which types compare, in which order things are evaluated and how values are encoded as Plutus Data. For a gentle introduction, start with values, functions and types.

Elci uses Elm 0.19 syntax for a functional core, with its own on-chain semantics. It is a development preview: the profile below is implemented and tested, and everything outside it is rejected with an error. The grammar defines the syntax exactly.

Feature matrix

Section titled “Feature matrix”
FeatureSupport
Modules and importsSource modules, as aliases, explicit exposing, exposing (..) for source modules, Type(..) for constructors, and Elm’s default imports. Import cycles are rejected.
FunctionsTop-level and local functions, lambdas with several arguments, curried and partial application, operators as functions such as (+).
Type signaturesRequired on every top-level declaration; allowed on local ones.
GenericsRank-1 type variables, specialized to each concrete use. Elm’s constrained variables comparable, appendable and compappend.

RecursionSelf-recursion and mutually recursive functions, top-level or local. Polymorphic recursion and recursive values are rejected.
Basic typesInt (arbitrary precision), Bool, String, (), Bytes, Data.
Core libraryThe Basics prelude and the List, Maybe, Result, Tuple and String modules, imported by default. See core modules.
ListsList a, literals, ::, ++ and list patterns.
TuplesPairs and triples, with patterns and destructuring.
RecordsClosed records, generic aliases with constructors, field access, accessor functions such as .name, update, destructuring.
Custom typesGeneric and recursive unions; Maybe is built in, and Result and Order come from the core library.
PatternsNested constructors, lists, cons, tuples, record fields, as, _, unit, and Bool, Int and String literals. Exhaustiveness and reachability are checked.
Equality and orderStructural == and /= for equality-capable types, and <, compare and sorting for comparable types (below).
Dictionaries, maps and arraysDict k v (Elm’s Dict, stored as a sorted Plutus map), Map k v (the ledger’s association map) and Array a (constant-time get).
ValuesValue, the ledger’s multi-asset value, with the core Value module: arithmetic, comparison and exact == on the CIP-153 builtins.

Java librariesJulc’s on-chain Java libraries and your own library JARs, including generic methods.
Validators[validators.<name>] scripts with spend, mint, withdraw, certify, vote and propose handlers, parameters and datum profiles.

Not supported: Float, / and number, typeclasses and user-defined constraints, extensible records and row polymorphism, higher-rank types, polymorphic recursion, ports and effects, Elm’s Set and Char modules and most of String, character literals, hexadecimal literals, %, tuples of four or more, and Elm packages.

Function and lambda parameters, and local destructuring, accept only irrefutable patterns: names, _, (), tuples and record fields. Anything that can fail to match belongs in case.

Layout

Section titled “Layout”

Indentation is significant, as in Elm. Top-level declarations start in column 1. The declarations of a let align with each other, and so do the branches of a case. A signature must directly precede its definition. Tabs are rejected. The grammar gives the exact layout rules.

Lexical rules

Section titled “Lexical rules”
  • Names. Values and functions start with a lowercase letter; types, constructors and module segments start with an uppercase letter. Letters, digits and _ may follow.
  • Reserved words. if, then, else, case, of, let, in, module, import, exposing, as, type and port. alias is only special after type. Don’t use them as names: the parser doesn’t yet reject every such use, as the grammar’s parser details describe.
  • Integers. Decimal digits only, arbitrarily large. 1.5 is rejected (Float is unsupported), and so are 0xFF and 1_000. elm-format 0.8.8 corrupts literals that do not fit in 64 bits, so check large constants after formatting.
  • Strings. Double-quoted, on one line. The escapes are \n, \r, \t, \" and \\. There are no triple-quoted strings, Unicode escapes or character literals.
  • Comments. -- to the end of the line, and {- ... -} blocks, which nest. {-| ... -} doc comments are ordinary block comments.

Imports and names

Section titled “Imports and names”

Every module has Elm’s default imports, which you don’t write:

Bytes, Dict, Map, Array, Value, Interval, Tx, Julc.Data and Java library modules are imported explicitly. Names resolve as in Elm, with one addition:

  • A module’s own declarations shadow every import.
  • Two imports that expose different things under one name make it ambiguous where it is used (ELCI2102). The message lists the qualified alternatives.
  • Addition: a name listed explicitly, as in import Utils exposing (clamp), takes precedence over a default import.
  • Qualified names such as Basics.max and Result.Ok always work. A qualified name is written without spaces and ends at its first lowercase part, so Config.settings.fee is the field fee of the value Config.settings.
  • A qualified name that doesn’t resolve is ELCI2104, with one of three messages: the module doesn’t expose the name, the module isn’t imported (with the import to add), or no imported module has that name. See diagnostics.
  • An import can’t be aliased to the name of another module, core or in the project: import Utils as String and import Julc.Interval as Interval are ELCI2104.

Core modules has the details and the messages.

Reserved names

Section titled “Reserved names”

  • Module names. Basics, List, Maybe, Result, String, Tuple, Map, Dict, Array, Value, Interval and Tx are core modules, and Set and Elci are reserved for the core library. Neither a project module nor a [java-modules] key can use these names, or a name that starts with Elci.:

    Bytes, Debug and Julc.Data belong to the compiler as well.

  • Constructors and types. A module can’t declare constructors named Just, Nothing, True or False, or types named Int, Bool, String, Bytes, Data, List, Maybe, Dict, Map, Array or Float:

    Other prelude names, such as Ok, Order or max, can be declared; your declaration shadows the prelude’s in your module.

  • Type names. Tuples are written ( a, b ) and unit (). Tuple Int Int gives ELCI2012: Write tuple types as ( a, b ) or ( a, b, c ), and Unit gives ELCI2012: Write the unit type as ().

Operators

Section titled “Operators”

From the tightest binding to the loosest:

PrecedenceOperatorsAssociativityMeaning
highestrecord.fieldfield access, written without spaces
10f xleftfunction application

8^rightinteger power
7*, //leftmultiplication, integer division truncating towards zero
6+, -leftaddition, subtraction
5::, ++rightlist cons; append lists or strings
4==, /=, <, >, <=, >=nonecomparisons; chaining is an error
3&&rightand, short-circuit

Operators of one precedence that group in opposite directions can’t be mixed without parentheses, as in Elm: f <| x |> g is ELCI1002: Mixing (<|) and (|>) needs parentheses: they associate in opposite directions, as in Elm, and the same holds for >> with <<.

  • +, -, *, // and ^ work on Int. 2 ^ 10 is 1024, 2 * 3 ^ 2 is 18, and a negative exponent fails the script.
  • <, >, <= and >= compare two values of the same comparable type.
  • == and /= work on equality-capable types (below).
  • / is rejected; use // for the integer quotient, and modBy or remainderBy for the rest. % does not exist.
  • a < b < c is rejected: write a < b && b < c.

Operators as functions

Section titled “Operators as functions”

Every binary operator can be used as a function by writing it in parentheses, as in Elm: (+), (*), (::), (++), (<), (^), (|>). (op) is the function \a b -> a op b, so (-) 10 subtracts from 10. (/) is rejected, like /. As functions, (&&) and (||) evaluate both arguments, like any other call.

Unary minus

Section titled “Unary minus”

Negation follows Elm 0.19. A - written directly before its operand, after a space or an opening bracket, negates it: f -1 passes -1 to f, and scale -x 10 passes -x. With a space after it, or with no space before it, - subtracts: x - 1 and x-1 are both subtractions. A leading - negates the whole function application that follows, so -(scale x 2) and -f x are negations of the result.

This is also how elm-format writes negative arguments, so formatted code keeps its meaning. As in Elm, x -1 is an application of x to -1, not a subtraction.

Equality

Section titled “Equality”

== and /= work on Int, Bool, String, (), Bytes, ledger hashes of the same type, Value, Data, and lists, tuples, records, Maybe, Dict and custom types whose contents are all equality-capable. Two dictionaries are equal when they have the same bindings, and two values when they hold the same quantities: every Value is kept in one canonical form, so == compares their encodings. Data compares structure exactly, so Tx.inlineDatum output == Just (Data.encode expected) checks a datum without decoding it. Imported types use the equality their provider approves (Java equals). Both operands are evaluated once, left to right.

Rejected with ELCI2003: functions, Map, Array, imported types without approved equality, and the ledger records that contain a Value (TxOut, TxInInfo, TxInfo). Ordering

Section titled “Ordering”

<, <=, >, >=, compare, min, max and the sorting functions take two values of the same comparable type:

  • Int, ordered numerically;
  • String, ordered by its UTF-8 bytes, which is Unicode code point order;
  • Bytes and the ledger’s byte-string types (PubKeyHash, ScriptHash, PolicyId, TokenName, TxId and the other hashes), ordered lexicographically by unsigned byte, a proper prefix first;
  • lists of a comparable type, lexicographically, and tuples of comparable types, component by component.

Bool, (), records, custom types, Maybe, Dict, Map, Array, Value, Data, functions and ledger records such as TxOutRef are not comparable (ELCI2003). Every order is total and agrees with ==. Comparing Int values uses the integer builtins; byte strings use lessThanByteString and lessThanEqualsByteString; String encodes both sides to UTF-8 and compares the bytes; lists and tuples use a comparison function generated once per type.

Ambiguous types

Section titled “Ambiguous types”

A type variable that nothing in a program determines, such as the element type of [] == [] or the error type of Ok 5, is ambiguous. As in Elm, such programs compile without annotations: no value of that type can exist, so any representation serves. List.length [] is 0, Result.withDefault 0 (Ok 5) is 5, and Julc.Data.encode Nothing is Constr 0.

Creating a value of the type still needs to know it. Julc.Data.decode and generic Java library functions report ELCI3001 and ask for an annotation:

Annotating the decoded value, as in a local amounts : List Int, fixes it.

Evaluation order

Section titled “Evaluation order”

Elci is strict. These rules are part of the language, because they decide which failures and costs happen:

  1. Application. The function, then its arguments from left to right. A partial application evaluates the arguments it has immediately.
  2. let. Every binding is evaluated, even if unused, before the body. Bindings run in dependency order; independent ones run in source order.
  3. Literals and constructors. List elements, tuple components, record fields and constructor arguments are evaluated from left to right, in source order. Record order does not follow the field names.
  4. Record update. The base record first, then the new field values in source order.
  5. Selective forms. if evaluates the condition and one branch. case evaluates the scrutinee once and one branch. && and || evaluate the right operand only when needed.
  6. Composition. f >> g evaluates f and g when the composition is built.
  7. Validators. Top-level values reachable from any handler are evaluated once per script run, before the purpose is dispatched.

Data encoding

Section titled “Data encoding”

Values that cross the script boundary (datums, redeemers, parameters) or pass through Julc.Data.encode use a fixed encoding:

Elci valuePlutus Data
Intinteger
Bytes, ledger hashesbyte string
Stringbyte string with the UTF-8 encoding
Boolconstructor 0 (False) or 1 (True), no fields
()constructor 0, no fields (as a datum or redeemer; Julc.Data.encode () is rejected)
recordconstructor 0, fields sorted by field name
tupleconstructor 0, fields in position order
custom typeconstructor tag = the variant’s position in the declaration, from 0; fields in order
Maybe aNothing is constructor 0; Just x is constructor 1 with one field
Result e aOk x is constructor 0 and Err e constructor 1, each with one field
OrderLT, EQ and GT are constructors 0, 1 and 2, no fields
JulcOptional aSome x is constructor 0 with one field; None is constructor 1
List alist
Dict k vmap with its keys in strictly ascending order
Map k vmap, in the map’s order
Valuemap from policy ids to maps from token names to quantities, both in ascending byte order, without zero quantities
imported record or sumas declared in Java: constructor in declaration order, fields in declaration order

Functions and arrays have no encoding. A Value can’t be a datum, redeemer or parameter yet, and a type that contains one can’t be decoded. You can see the encoding of any value with Julc.Data.encode and elci eval, which prints Data as Constr tag [fields], lists, {key: value} maps, integers and #bytes:

The record { beneficiary = 1, amount = 2 } encodes as Constr 0 [2, 1], because amount sorts before beneficiary.

Decoding is strict: tags, field counts and nested field kinds are checked, and a mismatch fails the script. A Dict, at any depth, must have strictly ascending keys: a map whose keys are out of order or repeated fails to decode. A Value must be canonical: its policies and token names strictly ascending, and no quantity zero. Each build records the encoding of its boundary types in abi.json; see datums and redeemers.

Compiler limits

Section titled “Compiler limits”
  • A program may create at most 256 specializations of generic functions.
  • Tuples have two or three elements.
  • The only target is plutus-v3-pv11-uplc-1.1.0.

For the error codes these rules produce, see diagnostics.
