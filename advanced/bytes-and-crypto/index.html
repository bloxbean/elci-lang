Bytes, hashes and bits

Byte strings are everywhere on Cardano: key hashes, script hashes, token names and transaction IDs are all bytes. This page walks through the Bytes module function by function, then covers hashes, signature checks and the Julc.ByteString helpers. Every example is a function project you can run with elci eval.

The Bytes type

Section titled “The Bytes type”

Bytes is a built-in type, so you can write it in any signature. The functions live in the compiler-provided Bytes module, which you import like any other module:

A few things to know before you start:

  • There is no byte literal. You create bytes with Bytes.fromString (UTF-8), Bytes.fromIntBigEndian, Bytes.replicate or Bytes.empty. In a real contract most bytes arrive in a datum, redeemer, parameter or the transaction itself.
  • Every function is a direct builtin call. There is no hidden loop, so each call is cheap and predictable.
  • The byte string comes last. Functions take the byte string as their final argument, so they read well in pipelines: name |> Bytes.take 4.
  • == compares bytes, and < orders them. Ledger hashes such as PubKeyHash are separate nominal types, even though they are byte strings underneath. They compare and order like bytes, but only with their own type. Use the .hash field to get their raw Bytes.

Building and slicing

Section titled “Building and slicing”

What this shows:

  • append a b puts a first. In a pipeline that reverses the reading order: name |> Bytes.append prefix produces prefix followed by name.
  • slice start count bytes takes a start index and a length, not an end index. It clamps to the available bytes instead of failing, and so do take and drop.
  • cons byte bytes and replicate count byte fail for a byte outside 0–255. replicate also fails above 8,192 bytes.

Reading and comparing

Section titled “Reading and comparing”
  • at index bytes returns a byte as an Int from 0 to 255. It fails outside the byte string.
  • <, <=, >, >= and compare order byte strings lexicographically by unsigned byte, so a proper prefix is smaller. Because bytes are comparable, min, max, List.sort and List.maximum work on them, and on ledger hashes such as PubKeyHash.
  • toString decodes UTF-8 and fails on invalid UTF-8.

The order is lexicographic, not numeric: the one byte #ff sorts after the two bytes #0001. To order byte strings as numbers, compare Bytes.toIntBigEndian of each.

Integer conversions

Section titled “Integer conversions”

fromIntBigEndian width n and fromIntLittleEndian width n write a non-negative integer into exactly width bytes. A width of 0 means “as few bytes as needed”. The to... functions read the bytes back as a non-negative integer.

Converting fails when the integer is negative (IntegerToByteString: negative integer), when it does not fit in the width (IntegerToByteString: integer doesn't fit in 1 bytes) or when the width exceeds 8,192 bytes.

A byte-string constant without a literal

Because Int is arbitrary precision, Bytes.fromIntBigEndian 32 n turns a decimal constant into a fixed-width byte string. Keys and hashes usually arrive as data or deployment parameters, so you rarely need this. If you do, note that elm-format 0.8.8 corrupts integer literals that do not fit in 64 bits, so check large constants after formatting.

Bit operations

Section titled “Bit operations”

Bits are numbered from the end of the byte string: bit 0 is the least significant bit of the last byte. Here f0 is the single byte 0xf0:

  • and, or and xor truncate to the shorter operand: 0xffff and 0xf0 give one byte.
  • shift n moves bits towards the front for positive n and towards the end for negative n. Bits shifted out are lost and the length stays the same. rotate n wraps them around instead.
  • testBit i reads bit i; findFirstSetBit returns the lowest set bit’s index, or -1 when no bit is set.

Hashes

Section titled “Hashes”

The six hash functions return fixed-length digests: blake2b224 gives 28 bytes (the size of key and script hashes), ripemd160 gives 20 bytes and the others give 32 bytes.

toHex is useful when you need hex as text, for example in a trace message. It is an ordinary recursive function: Bytes.toString (ByteString.toHex (Bytes.sha256 (Bytes.fromString "abc"))) cost about 73 million CPU units. Keep it out of a validator’s hot path.

Caution

intToDecimalString and utf8ToInteger do not validate their input. A negative number or a non-digit byte produces a meaningless result rather than a failure.

The full list of ByteStringLib exports is on the standard library page. Prefer the Bytes builtins where both exist.

When byte operations fail

Section titled “When byte operations fail”

A failing builtin fails the whole script, exactly like a validator returning False. There is no Maybe result to check. Guard the input first (for example compare the index with Bytes.length) when a failure would be wrong:

The command exits with status 1. The other failure messages you may meet are ConsByteString: byte value out of range: 256, ReplicateByte: length exceeds 8192, DecodeUtf8: invalid UTF-8 byte sequence and the IntegerToByteString errors above.
