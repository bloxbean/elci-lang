# ELCI3003: No Data encoding

A conversion to or from Plutus Data, or a generic Java library function, is used at a type that
has no Data encoding, or one it cannot handle.

Common causes:

- `Julc.Data.encode` or `Julc.Data.decode` of a function, `()` or an `Array`.
- Decoding a type with no strict decoder, such as `TxOut`, or a type that contains a `Value`.
- A generic Java library function used at a type that contains a `Dict`, which the library
  could build without checking its keys are in order, or a `Value`.

## Example

```elm
import Julc.Data as Data


main : Data
main =
    Data.encode (\n -> n + 1)
```

`elci check` reports:

```text
src/Main.elm:8:5: ELCI3003: No encoder for Int -> Int: functions have no Data encoding

8|     Data.encode (\n -> n + 1)
       ^^^^^^^^^^^
```

## Fix

Convert a Data-encodable type: `Int`, `String`, `Bytes`, `Bool`, a list, tuple, `Maybe`, record
or custom type of those, or a ledger type with an encoding.

```elm
import Julc.Data as Data


main : Data
main =
    Data.encode [ 1, 2 ]
```

For a `Value` inside other data, convert it with `Value.toList` and back with `Value.fromList`.
Pass a Java library a `Map` or a `List`, and build a `Dict` with `Dict.fromList`.
