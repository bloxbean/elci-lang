# ELCI2105: Unsupported Java export

A Java library module exports a function that Elci cannot call. The message gives the reason.

Common causes:

- A parameter or result type with no Elci equivalent, such as a Java tuple.
- A result that can hold a ledger `Value`. Java libraries build values in their own order, and
  Elci relies on every value being in the ledger's canonical order. Julc's `ContextsLib` and
  `OutputLib` are exempt, because they only pass along the ledger's own values.

## Example

```toml
[project]
source-directories = ["src"]
target = "plutus-v3-pv11-uplc-1.1.0"
julc-version = "0.1.0-pre20-ebaf028-SNAPSHOT"

[entrypoint]
module = "Main"
function = "main"
purpose = "function"
boundary = "julc-strict-v1"

[java-modules]
"Julc.Math" = "org.julclang.stdlib.lib.MathLib"
```

```elm
import Julc.Math as Math


main : Int
main =
    case Math.divMod 7 2 of
        _ ->
            0
```

`elci check` reports:

```text
src/Main.elm:8:10: ELCI2105: org.julclang.stdlib.lib.MathLib.divMod: Unsupported on-chain source type: Tuple2<BigInteger, BigInteger>

8|     case Math.divMod 7 2 of
            ^^^^^^^^^^^
```

## Fix

Use another export, or Elci's own operators and core modules:

```elm
import Julc.Math as Math


main : Int
main =
    Math.floorDiv 7 2 + Math.floorMod 7 2
```

For a `Value`, use the core `Value` module.
