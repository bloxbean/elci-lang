# ELCI2014: Handler signature does not match

A validator handler's type doesn't have the shape its `elci.toml` table needs. The handler
takes its arguments in this order:

1. the table's parameters;
2. the datum, for `spend`;
3. the redeemer;
4. the `ScriptContext`.

It returns `Bool`. The message gives the signature the table needs, how many parameters it
declares, the handler's type and the first pair of types that differ.

## Example

```toml
[project]
source-directories = ["src"]
target = "plutus-v3-pv11-uplc-1.1.0"
julc-version = "0.1.0-pre20-ebaf028-SNAPSHOT"

[validators.main]
boundary = "julc-strict-v1"
spend = "Main.spend"
```

```elm
module Main exposing (spend)

import Julc.Ledger exposing (ScriptContext)


spend : () -> ScriptContext -> Bool
spend _ _ =
    True
```

`elci check` reports:

```text
src/Main.elm:6:1: ELCI2014: Handler Main.spend does not have the spend signature datum -> redeemer -> ScriptContext -> Bool that [validators.main] needs (0 parameters); its type is () -> ScriptContext -> Bool; it has `Bool` where the configuration needs `ScriptContext -> Bool`

6| spend : () -> ScriptContext -> Bool
   ^^^^^

In elci.toml:6: [validators.main]
```

## Fix

Make the signature match the table. A spend handler takes a datum before its redeemer:

```elm
module Main exposing (spend)

import Julc.Ledger exposing (ScriptContext)


spend : () -> () -> ScriptContext -> Bool
spend _ _ _ =
    True
```

With `spend-datum = "optional"`, the datum's type is a `Maybe`.
