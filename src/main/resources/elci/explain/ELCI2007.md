# ELCI2007: Non-exhaustive case

A `case` doesn't handle every value it may be given. As in Elm, every `case` must be complete,
so a validator never meets a value its author didn't handle. The message lists the missing
patterns as you would write them, up to three.

## Example

```elm
type Action
    = Buy Int
    | Sell Int
    | Cancel


amount : Action -> Int
amount action =
    case action of
        Buy value ->
            value

        Sell value ->
            value


main : Int
main =
    amount Cancel
```

`elci check` reports:

```text
src/Main.elm:12:5: ELCI2007: This case does not cover every possibility; it is missing `Cancel`

12|     case action of
        ^^^^
Hint: add a branch for each missing pattern
```

## Fix

Add a branch for each missing pattern:

```elm
type Action
    = Buy Int
    | Sell Int
    | Cancel


amount : Action -> Int
amount action =
    case action of
        Buy value ->
            value

        Sell value ->
            value

        Cancel ->
            0


main : Int
main =
    amount Cancel
```

Prefer naming every constructor over `_ ->`. Adding a constructor later then points you to
every `case` to update.
