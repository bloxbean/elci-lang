# ELCI2003: Unsupported equality, ordering or append

An operation is used at a type that doesn't support it.

- **Equality** (`==`, `/=`): functions, a `Map`, an `Array` and some imported types such as
  `TxOut` have none.
- **Ordering** (`<`, `compare`, `max`, `List.sort` and the rest) needs a comparable type. The
  comparable types are:
  - `Int`, `String` and `Bytes`;
  - byte-string ledger types such as `PubKeyHash`;
  - lists and tuples of comparable types.

  Records, custom types and `Bool` are not comparable.
- **Append** (`++`) needs a `String` or a `List`.

A type variable that is compared or appended must say so with its name, as in Elm:
`comparable` or `appendable`. Elm's `number` is written `Int`. A `Dict` decoded from Data needs
comparable keys.

## Example

```elm
type alias Person =
    { name : String, age : Int }


main : List Person
main =
    List.sort [ { name = "Ann", age = 30 }, { name = "Bo", age = 25 } ]
```

`elci check` reports:

```text
src/Main.elm:10:5: ELCI2003: `List.sort` needs comparable values, but { age : Int, name : String } is not comparable. Comparable types are Int, String, Bytes, byte-string ledger types such as PubKeyHash, and lists and tuples of comparable types. Compare a comparable field instead, or sort with List.sortBy or List.sortWith

10|     List.sort [ { name = "Ann", age = 30 }, { name = "Bo", age = 25 } ]
        ^^^^^^^^^
```

## Fix

Compare a comparable field, here with `List.sortBy`:

```elm
type alias Person =
    { name : String, age : Int }


main : List Person
main =
    List.sortBy (\person -> person.age) [ { name = "Ann", age = 30 }, { name = "Bo", age = 25 } ]
```

Other fixes:

- For equality, compare the values you care about, such as a map's lookups, or keep keyed data
  in a `Dict`, which has equality.
- In an annotation, rename a compared type variable `comparable`, and an appended one
  `appendable`.
- For a `Dict` in data whose keys aren't comparable, use a `Map`.
