# ELCI4001: Invalid configuration or command line

`elci.toml`, a source file or the command line asks for something Elci cannot do. The message
says what to change. It is printed after `elci:`, without a source location.

Common causes:

- An unknown validator name after `--validator`, or an option that the command doesn't take.
- A value in `elci.toml` that isn't one of those allowed, such as an unknown purpose.
- A `[java-modules]` key that names a core module.
- An `elci apply` parameter that doesn't fit its type, such as a `Dict` whose keys are not in
  ascending order.
- A source file that is not UTF-8 text.

## Example

```toml
[project]
source-directories = ["src"]
target = "plutus-v3-pv11-uplc-1.1.0"
julc-version = "0.1.0-gb-5a3378b"

[entrypoint]
module = "Main"
function = "main"
purpose = "fun"
boundary = "julc-strict-v1"
```

```elm
main : Int
main =
    1
```

`elci check` reports:

```text
elci: ELCI4001: Unsupported purpose: fun; [entrypoint] only supports purpose = "function"
```

## Fix

Change what the message names. Here the purpose of an `[entrypoint]` is `function`:

```toml
[project]
source-directories = ["src"]
target = "plutus-v3-pv11-uplc-1.1.0"
julc-version = "0.1.0-gb-5a3378b"

[entrypoint]
module = "Main"
function = "main"
purpose = "function"
boundary = "julc-strict-v1"
```
