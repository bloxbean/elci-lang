# ELCI3001: Type is not known where it is used

An operation needs to know a type that nothing in the program determines.

Most code works without it: `List.length []` is `0`, as in Elm. The operations that create a
value of the type need it:

- `Julc.Data.decode`, which picks a decoder by the type;
- a generic Java library function, including one a core module such as `Map` uses.

## Example

```elm
import Julc.Data as Data


main : Int
main =
    List.length (Data.decode (Data.encode [ 1, 2 ]))
```

`elci check` reports:

```text
src/Main.elm:8:18: ELCI3001: Cannot determine the type converted by Julc.Data.decode; add a type annotation

8|     List.length (Data.decode (Data.encode [ 1, 2 ]))
                    ^^^^^^^^^^^
```

`List.length` works on any list, so nothing tells Elci what the decoded list contains.

## Fix

Give the value a type, for example with an annotated `let` binding:

```elm
import Julc.Data as Data


main : Int
main =
    let
        amounts : List Int
        amounts =
            Data.decode (Data.encode [ 1, 2 ])
    in
    List.length amounts
```
