# ELCI2013: Type cannot cross the boundary

A validator's datum, redeemer and parameters arrive on chain as Plutus Data. Each of their
types needs a strict Data encoding that Elci can check when it decodes them. This type has none.

Common causes:

- A function type.
- A `Value`, or a ledger type that contains one, such as `TxOut`.
- An `Array`, which has no Data encoding anywhere in data, in any project.

## Example

```toml
[project]
source-directories = ["src"]
target = "plutus-v3-pv11-uplc-1.1.0"
julc-version = "0.1.0-gb-5a3378b"

[validators.main]
boundary = "julc-strict-v1"
mint = "Main.mint"
```

```elm
module Main exposing (mint)

import Julc.Ledger exposing (ScriptContext)


mint : (Int -> Int) -> ScriptContext -> Bool
mint _ _ =
    True
```

`elci check` reports:

```text
src/Main.elm:6:1: ELCI2013: Functions cannot be serialized as datum or redeemer

6| mint : (Int -> Int) -> ScriptContext -> Bool
   ^^^^

In elci.toml:6: [validators.main]
```

## Fix

Use a type with a Data encoding: your own record or custom type, or a ledger type with an
approved boundary such as `TxOutRef` or `PubKeyHash`.

```elm
module Main exposing (mint)

import Julc.Ledger exposing (ScriptContext)


mint : Int -> ScriptContext -> Bool
mint _ _ =
    True
```

For an amount of tokens, store a `List ( PolicyId, TokenName, Int )`, and rebuild the value with
`Value.fromList`. Keep an `Array`'s elements in data as a `List`, and convert with
`Array.fromList`.
