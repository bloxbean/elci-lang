# ELCI2002: Type mismatch

A value has a different type from the one its place in the program needs. The message names
that place and both types.

The place can be:

- an argument to a function, or a value piped in with `|>`;
- the condition or a branch of an `if`, or a branch of a `case`;
- a list element, a pattern or an operator's side;
- a record field;
- the body of a declaration, against its annotation.

It is also reported when a function gets more arguments than it takes, and when a type would
have to contain itself.

## Example

```elm
main : String
main =
    String.fromInt "42"
```

`elci check` reports:

```text
src/Main.elm:6:20: ELCI2002: The 1st argument to `String.fromInt` is `String`, but `String.fromInt` needs `Int`

6|     String.fromInt "42"
                      ^^^^
```

## Fix

Give the place a value of the type it needs, or change what it needs:

```elm
main : String
main =
    String.fromInt 42
```

For types that are often confused, the hint names the conversion:

- `String.fromInt` between an `Int` and a `String`;
- `Bytes.fromString` between a `String` and `Bytes`;
- a `case` or `Maybe.withDefault` for a `Maybe`;
- `Value.lovelaceOf` for the lovelace in a `Value`.

When an annotation says `a` can be any type, but the definition needs a specific one, write that
type in the annotation.
